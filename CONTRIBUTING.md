# Contributing to Crimp

Crimp is early-stage — architecture and conventions are still settling. If you want to contribute beyond a small fix, open an issue first to discuss direction before writing code.

## Workflow

- Every change goes through a pull request. No direct pushes to `main`.
- Keep commits small and scoped to one logical change. Use [Conventional Commits](https://www.conventionalcommits.org/) style prefixes: `feat:`, `fix:`, `chore:`, `test:`, `docs:`, `build:`, `ci:`.
- PRs need explicit maintainer approval before merge.

## Reporting security issues

Do not open a public issue for a security vulnerability in Crimp itself. See [SECURITY.md](SECURITY.md) instead.
